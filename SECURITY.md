# Security Policy

## Supported versions

CYOA is a self-hosted application distributed as a container image from GHCR. There is no long-term support branch — the latest published image is the supported one, and fixes land on `main` and are republished rather than backported.

## Reporting a vulnerability

If you find a security issue, please report it privately rather than opening a public issue.

**How to report:**
Use GitHub's private vulnerability reporting feature:
`Security` tab → `Report a vulnerability`

**Response time:**
This is a solo-maintained hobby project. Expect an initial response within 7 days. Critical issues will be prioritized.

## Threat model

Two things shape what counts as a vulnerability here.

**A story file is untrusted input.** Stories are written by other people or generated by an LLM, and the whole point of the engine is to run one it has never seen. A story file that can execute code, read files outside its directory, or inject script into a reader's page is a vulnerability, not a malformed story. Two defences carry most of this weight, and both have tests:

- **Story content is never `eval`'d.** This is constraint 1 in `CLAUDE.md` and it has no exceptions. When passages eventually get conditions, they get a restricted expression evaluator; the lazy implementation would turn every story file into a remote-code-execution vector.
- **Story slugs arrive from URLs and are validated before touching the filesystem.** A slug must be a single safe path segment, so `../` cannot walk out of the stories directory. See `library/loader.py` and the traversal tests in `tests/test_library.py`.

Prose is also rendered with raw HTML disabled, so a story cannot inject markup into a reader's page.

**v1 has no authentication, and that is deliberate.** ADR-006: there are no accounts, no login, and no admin interface, because there is nothing to protect — the app is read-only and stores only a reader's position. Anyone who can reach the app can read every story on it. If you expose an instance publicly and that is not what you want, put it behind your own auth at the proxy. Authentication arrives with the story editor, not before.

**v1 makes no outbound network calls.** The book plays offline. The optional LLM provider on the roadmap is the only thing that will ever change this, and it stays off by default.

## Secrets

No secrets live in the repository. Configuration comes from the environment with a `CYOA_` prefix; `.env` is gitignored and `.env.example` carries names and never values. A credential committed by accident is a reportable issue.

## Dependency vulnerabilities

Dependabot runs weekly against three ecosystems:

| Ecosystem | What it covers |
|---|---|
| `pip` | Python dependencies declared in `pyproject.toml` |
| `docker` | The base image in `Dockerfile` |
| `github-actions` | Actions pinned in `.github/workflows/` |

The vendored copy of htmx in `src/cyoa/web/static/js/` is **not** covered by Dependabot — it is a committed file, not a declared dependency (ADR-002: no bundler, no `node_modules`). Updating it is a manual step.

If you spot a vulnerable dependency Dependabot hasn't caught, please report it using the process above.
